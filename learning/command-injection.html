What is Command Injection?

Sometimes a website runs a program on the server's operating system, for example a "ping" tool that checks if an address is online.

Command injection happens when user input is added to that command. Special characters let the attacker add their own commands, which then run on the server.

How does it work?

On Linux and Windows, characters like ;, && and | join commands together. If the input contains one of them, the shell runs the website's command and then the attacker's command.

User input8.8.8.8; cat /etc/passwd
→
Serverruns ping -c 4 + input
→
Shellruns both commands

Why is it dangerous?

  • The attacker can run any command the web server is allowed to run.
  • They can read files, install malware or move to other systems.
  • It often leads to full control of the server.

A simple example

PayloadsAllTheThings shows this PHP code that pings an address typed by the user:

<?php
    $ip = $_GET['ip'];
    system("ping -c 4 " . $ip);
?>

If the input is 8.8.8.8; cat /etc/passwd, the command that runs is:

ping -c 4 8.8.8.8; cat /etc/passwd

The ; ends the ping command and starts a new one. cat /etc/passwd prints a system file, which proves the attacker's command ran.

More examples: Command Injection on our Cheatsheet.

How to identify it during authorised testing

  1. Look for features that clearly use system tools: ping, traceroute, file conversion, DNS lookup.
  2. On an authorised lab, add a separator such as ;, && or | followed by a harmless command.
  3. If nothing is shown, test with a time delay such as sleep 5 and measure the response time.

Common mistakes developers make

  • Passing user input to functions like system() or exec().
  • Blocking a few characters only. PayloadsAllTheThings lists many ways around such filters.
  • Running the web server as an administrator.

How developers can prevent it

  • Avoid calling system commands. Use the programming language's built-in functions instead.
  • If a command is needed, use an allow list (for example, input must be a valid IP address).
  • Pass arguments separately instead of building one command string.
  • Run the web server with the lowest possible permissions.
