What is Path Traversal?

Some websites load files using a name from the URL, for example image?file=cat.png.

Path traversal (also called directory traversal) happens when the user can add ../ to the file name and move out of the intended folder to read other files on the server.

How does it work?

On computers, ../ means "go up one folder". If the server adds the user's file name to a folder path without checking it, enough ../ steps reach the top of the disk, and then any file can be named.

Requestfile=../../../etc/passwd
→
Serverjoins it to /var/www/images/
→
Resultreads /etc/passwd

Why is it dangerous?

  • Attackers can read passwords, keys and configuration files.
  • Reading source code helps attackers find more bugs.
  • If files can also be written, it can lead to full server control.

A simple example

The server builds the path like this:

/var/www/images/ + INPUT

PayloadsAllTheThings lists ../ and several encoded versions that may get past simple filters:

../
..\
%2e%2e%2f
%252e%252e%252f
..././

%2e%2e%2f is ../ written with URL encoding. %252e is encoded twice. ..././ becomes ../ again if a filter removes ../ only once. A common test target on Linux is the readable file /etc/passwd.

More examples: Path Traversal on our Cheatsheet.

How to identify it during authorised testing

  1. Look for parameters that look like file names, such as file=, page= or download=.
  2. Try ../ sequences on an authorised lab and check if the response changes.
  3. Try encoded versions if plain ../ is blocked.

Common mistakes developers make

  • Joining user input to a folder path directly.
  • Blocking only the exact text ../.
  • Running the web server with permission to read every file.

How developers can prevent it

  • Do not use user input in file paths. Use a list of allowed files or IDs instead.
  • If a name is needed, allow only letters and numbers.
  • Resolve the final path and check that it is still inside the allowed folder.
  • Run the web server with as few file permissions as possible.
