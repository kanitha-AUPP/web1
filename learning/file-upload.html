File Upload Vulnerabilities

What is File Upload?

Many websites let users upload files such as profile pictures or documents.

A file upload vulnerability happens when the website does not check uploads properly. An attacker can upload a file that the server runs as code, or a file that harms other users.

How does it work?

If the server saves an uploaded .php file inside a public folder, visiting that file's URL makes the server run it. That gives the attacker a way to run their own code on the server.

Attackeruploads shell.php as a "picture"
→
Serversaves it in /uploads/
→
Attackeropens /uploads/shell.php

Why is it dangerous?

  • Running uploaded code can give full control of the server.
  • Uploaded HTML or SVG files can contain XSS.
  • Very large files can fill up the disk.

A simple example

A simple filter only checks the file extension. PayloadsAllTheThings lists extension tricks that may get past it:

.jpg.php
.php.jpg
.pHp
.php%00.jpg

Another check that is easy to fool is the Content-Type header, which the browser (or attacker) sends:

Content-Type: image/gif

A double extension, mixed upper and lower case, or a null byte (%00) can confuse a weak filter. Changing Content-Type to image/gif makes a script look like an image, because the server trusts what the request says.

More examples: File Upload on our Cheatsheet.

How to identify it during authorised testing

  1. Find every upload form, including profile pictures and document imports.
  2. On an authorised lab, upload a harmless text file renamed with different extensions and see which are accepted.
  3. Check where uploaded files are stored and whether they can be opened by URL.

Common mistakes developers make

  • Checking only the extension or only the Content-Type header.
  • Using a block list ("no .php") instead of an allow list.
  • Keeping the user's original file name.
  • Storing uploads in a folder where the server runs scripts.

How developers can prevent it

  • Allow only the file types you need (for example .jpg and .png).
  • Rename every file to a random name chosen by the server.
  • Store uploads outside the web folder, or on a separate domain.
  • Limit the file size and check the real file content.
