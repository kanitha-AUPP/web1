What is Authentication?

Authentication is how a website checks who you are, usually with a username and password.

Authentication vulnerabilities are weaknesses in login, registration, "forgot password" or session handling that let someone log in as another user. This is often called account takeover.

How does it work?

Attackers look for the weakest step in the login process. It might be no limit on password guesses, a password reset link that can be predicted, or a reset email that can be sent to the attacker instead of the real user.

Why is it dangerous?

  • The attacker becomes the victim and can do anything the victim can.
  • Admin accounts give control of the whole website.
  • Users often reuse passwords, so one leak can affect other websites too.

A simple example

PayloadsAllTheThings lists tests for the "forgot password" form. For example, sending two email addresses in the same request (parameter pollution):

email=victim@mail.com&email=hacker@mail.com

or sending them as a list in a JSON request:

{"email":["victim@mail.com","hacker@mail.com"]}

A badly written reset function might look up the victim's account using the first email but send the reset link to every address in the request, including the attacker's.

More examples: Authentication on our Cheatsheet.

How to identify it during authorised testing

  1. Check if there is a limit on wrong password attempts.
  2. Request two reset tokens and compare them. Are they random? Do they expire?
  3. Check whether error messages reveal if a username exists.
  4. Log out and check whether the old session cookie still works.

Common mistakes developers make

  • Allowing unlimited login attempts.
  • Reset tokens that are short, predictable or never expire.
  • Different error messages for "wrong username" and "wrong password".
  • Not ending the session on logout or after a password change.

How developers can prevent it

  • Limit login attempts and add multi-factor authentication (MFA).
  • Make reset tokens long, random, single-use and short-lived.
  • Show the same message for every failed login.
  • Create a new session ID after login, and end it on logout.
