What is Security Misconfiguration?

Security misconfiguration means the code may be fine, but the server, framework or cloud service is set up in an unsafe way.

Examples include default passwords, admin panels open to the internet, detailed error pages and unsafe CORS settings.

How does it work?

Software often comes with default settings that make setup easy but are not safe. If developers forget to change them before going live, attackers can use well-known defaults that are listed online.

Why is it dangerous?

  • Default passwords are public, so they are the first thing attackers try.
  • Error pages can reveal file paths, versions and code.
  • Exposed admin tools can give full control of the server.

A simple example

PayloadsAllTheThings describes admin panels "exposed via predictable URLs" with default credentials such as admin/admin. A tester may check addresses like:

https://example.com/admin

Another misconfiguration is CORS that trusts any website. PayloadsAllTheThings shows a server copying the Origin header back into its response:

Origin: https://evil.com

Access-Control-Allow-Origin: https://evil.com
Access-Control-Allow-Credentials: true

Because the server allows https://evil.com with credentials, a script on that website could read the logged-in user's private data from the API.

More examples: Security Misconfiguration on our Cheatsheet.

How to identify it during authorised testing

  1. Look for admin, login and debug pages at common addresses.
  2. Trigger an error (for example, a wrong URL) and read the error page.
  3. Check response headers for software versions and security headers.
  4. Send a request with Origin: https://evil.com and see if it comes back.

Common mistakes developers make

  • Not changing default usernames and passwords.
  • Leaving debug mode on in production.
  • Copying CORS settings that allow every origin.
  • Leaving unused pages, sample files and services online.

How developers can prevent it

  • Change all default passwords before going live.
  • Turn off debug mode and show simple error pages.
  • Only allow trusted origins in CORS.
  • Remove features you do not use, and review settings regularly.
