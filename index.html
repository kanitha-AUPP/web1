What is Web Application Penetration Testing?

A web application penetration test is an authorised, simulated attack on a website. The tester looks for weaknesses the same way a real attacker would, and then writes a report so the owners can fix the problems before someone abuses them.

It usually follows five steps:

  1. Planning and scope - agree in writing what may be tested.
  2. Reconnaissance - learn how the website works.
  3. Scanning - look for possible weaknesses.
  4. Exploitation - safely prove that a weakness is real.
  5. Reporting - explain the problem and how to fix it.

Video: "ALL of Web Hacking in 7 Minutes" by CyberFlow (YouTube).

Why should beginners learn web security?

Websites are everywhere

Banking, shopping, school portals and social media all run as web applications. One small mistake can expose thousands of users.

Better developers

When you know how attacks work, you write safer code from the start instead of fixing problems later.

A growing career

Security testers, bug bounty hunters and secure developers are in demand, and web security is a common first step.

About us

WebPenTest 101 is our final project for INFO 250. We wanted a place where a beginner can see how penetration testing is organised, read about common problems like injection and the OWASP Top 10, and find safe places to practise.

It is a starting point, not a complete course. When you finish here, the References page tells you where to go next.

Ethical hacking means permission first. Never test a website you don't own or haven't been explicitly allowed to test.
